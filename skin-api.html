五菱车控 · 外观与布局

皮肤格式说明

一份皮肤就是一个 .json 文件，只描述颜色、圆角与玻璃厚薄 —— 不改布局、不改功能、不执行任何代码。

本页只从 App 内的「外观与布局」进入，官网首页没有入口。
内容随版本更新，以 App 内的「保存模板」为准；窄屏上表格可左右滑动。

01三步做出一套皮肤

  1. App 里打开 我的 → 外观与布局 → 外观，往下滚到「皮肤」那一片，点 保存模板，存到任意位置。
  2. 用文本编辑器改颜色值；或者把下面的 AI 提示词丢给任意对话式 AI，让它直接生成一份。
  3. 回到工坊点 导入皮肤 JSON，选中文件。导入后点卡片即应用。

改坏了不要紧：导入失败会提示原因，已有皮肤不受影响；应用后想还原，点来源条右侧的 卸下皮肤。

02文件结构

{
  "schemaVersion": 1,
  "name": "纸白",
  "author": "官方",
  "mode": "light",
  "tokens": {
    "pageBg": "#F4F1EA",
    "cardBg": "#FFFDF8",
    "primary": "#C4703A",
    "onPrimary": "#FFFFFF",
    "textPrimary": "#2A2622",
    "textSecondary": "#6B6459",
    "radiusCard": 14,
    "glassAlpha": 1.0
  }
}

顶层字段

字段必填说明
schemaVersion否1 = 单态（一套颜色）；2 = 双态（深浅各一套）；3 = 带布局。不填按 1 处理
name必填皮肤名，最多 24 个字符，超出整份文件判为无效
author否作者名，超 24 字符会被截断（不会报错）
mode否"dark" / "light"，默认 "dark"。仅单态皮肤有效
tokens必填一套颜色，见下表
lightTokens否仅双态皮肤使用，见第 03 节
layout否布局规格（密度 / 卡片形态 / 列数 / 首页区块），见第 04 节

tokens 的 8 个字段

字段必填取值作用
pageBg必填#RRGGBB页面底色，整个 App 的底
cardBg必填#RRGGBB卡片底色，所有玻璃卡片的填充
primary必填#RRGGBB强调色：按钮、选中态、图标、距离胶囊底
onPrimary必填#RRGGBB压在 primary 上的字色
textPrimary必填#RRGGBB主文字：标题、数值
textSecondary必填#RRGGBB次要文字：副标题、说明、标签
radiusCard否0 ~ 28卡片圆角（dp），默认 18
glassAlpha否0 ~ 1卡片不透明度，1 = 实心，默认 0.92

颜色只接受 #RRGGBB（推荐，大写）或 #AARRGGBB。不要写 #RGB 三位缩写、rgb() 或颜色名 —— 都会被判无效。

03双态皮肤

单态皮肤只能声明一种明暗，应用后会强制把 App 切到那个模式。双态皮肤自带深浅两套，应用后不再强制模式，跟随用户自己的「跟随系统 / 深色 / 浅色」设置。

{
  "schemaVersion": 2,
  "name": "晨昏",
  "author": "",
  "mode": "dark",
  "tokens": {
    "pageBg": "#0D0A14", "cardBg": "#171226",
    "primary": "#B794FF", "onPrimary": "#1A1030",
    "textPrimary": "#F2ECFF", "textSecondary": "#9C93B8",
    "radiusCard": 18, "glassAlpha": 0.85
  },
  "lightTokens": {
    "pageBg": "#F6F2FF", "cardBg": "#FFFFFF",
    "primary": "#6B4FD8", "onPrimary": "#FFFFFF",
    "textPrimary": "#1C1530", "textSecondary": "#5C5478",
    "radiusCard": 18, "glassAlpha": 1.0
  }
}
  • tokens 在双态里表示深色那套，lightTokens 表示浅色那套。
  • lightTokens 要么不给，要么 6 个颜色全给。只写一半会让整份文件无效 —— 半套会渲染出深浅混杂的结果，比直接失败更难排查。
  • mode 在双态里不起作用。
  • 双态文件在旧版本 App 里仍能导入，但只会用 tokens 那套，并被当成单态皮肤强制深色。

04布局（可选）

除颜色之外，皮肤还可以带一套布局：间距密度、卡片形态、车辆数据的列数，以及首页区块的顺序与显隐。整块可以缺省 —— 不带就完全沿用用户自己的布局。

{
  "schemaVersion": 3,
  "name": "极简白",
  "tokens": { ... },
  "layout": {
    "density": "compact",
    "cardStyle": "plain",
    "dataColumns": 2,
    "home": {
      "order": ["status", "data", "quick", "bottom"],
      "hidden": ["bottom"]
    }
  }
}

layout 的字段

字段取值说明
densitycompact / standard / roomy区块之间的间距：12 / 20 / 28dp。默认 standard（也就是不带布局时的样子）
cardStylecard / plaincard = 玻璃卡片；plain = 不画底、不投影，只在块之间留一条细线。默认 card
dataColumns4 / 2车辆数据卡每行几个数。默认 4
home.order区块 id 数组首页顺序，可选 status（车辆概览）/ quick（快捷控制）/ data（车辆数据）/ bottom（开闭与控车）
home.hidden区块 id 数组首页要隐藏的区块
  • 每个字段都能单独缺省，没写的按默认值算。写错一个值（比如 "density": "loose"）只会让那一个字段被忽略，皮肤照常导入 —— 这一点和颜色相反：颜色错一个值会整份作废，因为那会画出读不了的界面；布局错一个值只是排列不同。
  • home.order 里没列出的区块会自动追加到末尾，所以写一半也行。配置里出现不认识的 id 会被忽略（比如以后删掉的区块）。
  • 没有 3 列：8 项在 3 列下排成 3+3+2，最后一行缺一个角，比 4 列更难看。
  • 布局是整体让位的：用户只要在 App 里调过一次布局，皮肤这套就完全不生效了。原因是顺序和显隐强相关 —— 半套合并会得到一套你没设计过、用户也没见过的排列。用户可以在「外观与布局 → 布局」里点「恢复皮肤布局」让你的布局重新生效。
  • 带了布局的皮肤，卡片上会多一行「带布局」，用户在应用前就知道它会连排布一起换掉。

05配色原则

  1. 文字与底色：textPrimary 对 pageBg ≥ 7:1；textSecondary ≥ 4.5:1。低于 4.5 的字在户外强光下基本不可读。
  2. onPrimary 对 primary：最低 3:1，建议 4.5:1。这是最容易被忽略的一对 —— 主色按钮上的字糊了，整个界面就显得廉价。
  3. cardBg 与 pageBg 只差一点点（亮度差 3%~8%）。差太多会变成「一块块补丁」，差太少卡片边界只能靠描边撑住。
  4. primary 别太刺。它会被大面积使用（底部距离胶囊、按钮），高明度高饱和的纯色在浅色底上会非常扎眼。
  5. 只用一個强调色。多色强调会让「哪个是主操作」失去答案。

两套示例的实测值

示例主文字 / 底次文字 / 底按钮字 / 主色
纸白（浅色）13.3 : 15.18 : 13.67 : 1
晨昏 · 深色17.0 : 16.80 : 17.49 : 1
晨昏 · 浅色15.9 : 16.37 : 15.62 : 1

纸白那栏的 3.67 是这套皮肤的真实值 —— 够用但不宽裕。自己做的时候把 onPrimary 往黑白两端再推一点就有余量了。

06为什么导入会失败

提示原因
「这个文件不是有效的皮肤」不是 JSON / 超过 64 KB / 缺 name 或超 24 字符 / 缺 tokens / 6 个颜色有缺失或格式不对 / 写了 lightTokens 但没给全
「皮肤已达 32 份上限」导入的皮肤最多 32 套，先删几套再导入
  • 同名覆盖：导入与已有皮肤同名的（非内置）会覆盖旧的，并把「使用中」迁到新版本 —— 作者改版直接重新导入即可，不会多出一张卡。
  • 内置的 6 套不能删除，也不能被导入的同名皮肤顶掉。

07AI 提示词

把下面整段复制给任意对话式 AI（ChatGPT / Claude / 豆包 / 通义都行），把「风格」那一行换成你想要的描述即可。它应该只回一段 JSON。

单态版一套颜色

你是 UI 配色设计师。请为「五菱车控」这款 Android App 设计一套皮肤，输出一份 JSON。

【风格】
（在这里写你要的风格，一句话即可。例：深夜的深海蓝，强调色用电光青，冷静克制）

【输出格式】
只输出 JSON，不要任何解释文字，不要 markdown 代码块。结构必须严格如下：

{
  "schemaVersion": 1,
  "name": "皮肤名",
  "author": "",
  "mode": "dark",
  "tokens": {
    "pageBg": "#000000",
    "cardBg": "#000000",
    "primary": "#000000",
    "onPrimary": "#000000",
    "textPrimary": "#000000",
    "textSecondary": "#000000",
    "radiusCard": 18,
    "glassAlpha": 0.9
  }
}

【字段规则】
- name：中文 2~6 个字，概括风格，不要出现「皮肤」「主题」这类词。
- author：留空字符串。
- mode：只能填 "dark" 或 "light"，表示这套配色本身是深色还是浅色。
- 6 个颜色一律写成 #RRGGBB，字母大写。不要写 #RGB 缩写、不要写 rgb()、不要写颜色名。
- radiusCard：整数，范围 0~28。锐利风格取 8~12，柔和风格取 18~22。
- glassAlpha：0~1 的小数，是「卡片不透明度」。实体纸张感填 1.0，通透玻璃感填 0.8~0.9。

【配色硬约束（务必逐条自检）】
1. textPrimary 与 pageBg 的对比度 ≥ 7:1。
2. textSecondary 与 pageBg 的对比度 ≥ 4.5:1。
3. onPrimary 与 primary 的对比度 ≥ 4.5:1（最低 3:1）。
4. cardBg 与 pageBg 只差一点：亮度差 3%~8%。
5. 只用 primary 一个强调色，不要引入第二个高饱和色。
6. primary 不要用纯红 #FF0000、纯绿 #00FF00 这类极端值。

【自检】
输出前在心里核对一遍第 1~3 条的对比度数值，不满足就调整颜色，直到满足。只输出最终 JSON。

双态版深浅各一套

你是 UI 配色设计师。请为「五菱车控」这款 Android App 设计一套同时提供深色与浅色的皮肤，输出一份 JSON。

【风格】
（在这里写你要的风格，例：晨雾里的紫与米白，安静、低饱和）

【输出格式】
只输出 JSON，不要任何解释文字，不要 markdown 代码块。结构必须严格如下：

{
  "schemaVersion": 2,
  "name": "皮肤名",
  "author": "",
  "mode": "dark",
  "tokens": {
    "pageBg": "#000000", "cardBg": "#000000",
    "primary": "#000000", "onPrimary": "#000000",
    "textPrimary": "#000000", "textSecondary": "#000000",
    "radiusCard": 18, "glassAlpha": 0.85
  },
  "lightTokens": {
    "pageBg": "#FFFFFF", "cardBg": "#FFFFFF",
    "primary": "#000000", "onPrimary": "#FFFFFF",
    "textPrimary": "#000000", "textSecondary": "#000000",
    "radiusCard": 18, "glassAlpha": 1.0
  }
}

【字段规则】
- tokens 是深色那套，lightTokens 是浅色那套。两套都必须把 6 个颜色写全，少一个字段整份文件就作废。
- 两套的 radiusCard 建议保持一致。
- 两套的 primary 可以是同一色相的不同明度，但都要满足对比度要求。
- 颜色格式、name、author、取值范围同单态版。

【配色硬约束（两套分别自检）】
1. textPrimary 与 pageBg 对比度 ≥ 7:1。
2. textSecondary 与 pageBg 对比度 ≥ 4.5:1。
3. onPrimary 与 primary 对比度 ≥ 4.5:1（最低 3:1）。
4. cardBg 与 pageBg 亮度差 3%~8%。
5. 深浅两套要让人一眼看出是同一套设计：色相、风格、圆角一致，只换明暗。

拿到结果后，按这几句微调

  • 字太浅了：「textSecondary 再暗一点（深色皮肤）／再深一点（浅色皮肤），保证对 pageBg 至少 4.5:1，其余不动，重新输出完整 JSON。」
  • 卡片和背景分不开：「cardBg 与 pageBg 的亮度差再拉开一点，控制在 6%~8%，其余不动。」
  • 太透了：「glassAlpha 改成 1.0，其余不动。」
  • 圆角不合适：「radiusCard 改成 12，其余不动。」
  • 想要另一明暗：「保持这套的色相与风格，反过来做一套浅色（或深色）版本，用 schemaVersion 2 的双态格式输出完整 JSON。」

收到结果后自查：是否纯 JSON（没有「好的，这是……」开头、没有代码块包裹）／6 个颜色是否都是 7 位 #RRGGBB／name 是否 ≤ 24 字符／双态版 lightTokens 是否齐全。有一条不对就让 AI 修正，不要手改 —— 手改容易漏字段，导入会直接失败。
